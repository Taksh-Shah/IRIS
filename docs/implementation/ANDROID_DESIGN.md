## 1. Scope

Build the **Android application shell + Kotlin FFI adapter layer** that hosts the
Rust `iris-core` engine on Android, mirroring the DESKTOP-001 `DesktopEngine`
pattern (TransportManager + register transports + MessageEngine + auto inbox
forwarder). All protocol/routing/crypto/storage logic stays in Rust (`iris-core` +
`iris-storage`); the Kotlin layer provides the **Android system-context plumbing**
(FGS, permissions, lifecycle, broadcast receivers, notifications) and the
**platform adapter implementations** (BLE, Wi-Fi Aware, Wi-Fi Direct) injected
into Rust via **UniFFI foreign traits** (`#[uniffi::export(foreign)]` proc-macro
+ async trait methods over FFI — RES-0022 Q1).

**Net-new deliverables** (nothing exists in-repo today — no `android/`/`kotlin/`
dir, no `.udl`/uniffi, per iter-110 evidence):

1. `crates/iris-android` — Rust FFI crate: UniFFI binding layer
   (`#[uniffi::export]` object + foreign-trait wiring), builds to `libiriscode.so`
   via **cargo-ndk** for {arm64-v8a, armeabi-v7a, x86_64}.
2. `kotlin/` (+ `android/` Gradle module) — Kotlin 2.2.x/Compose app shell:
   Hilt MVVM, `IrisEngine` facade (generated by UniFFI, committed), Kotlin
   adapters `AndroidBleTransportAdapter` / `AndroidWifiAwareTransportAdapter` /
   `AndroidWifiDirectTransportAdapter` implementing the foreign traits,
   FGS `connectedDevice` (API 34+), PendingIntent BLE scanning, WorkManager
   cadence, Keystore TEE Ed25519 identity provisioning.

**Explicitly deferred** (recorded, not blockers): physical-device/battery/OEM
integration tests (BLK-0005), iOS (IOS-001), LoRa/SAT (P2), production signing/
release automation, store UI flows, onboarding UX polish, Wi-Fi Aware NCS/Pairing
v2 hardening (RES-0020 R2 optional tier).

## 2. Design decisions (RES-0022 Q1-Q5 absorbed, D-1..D-7)

| # | Decision | Basis (RES-0022) |
|---|----------|-------------------|
| D-1 | **UniFFI foreign traits** (`#[uniffi::export(foreign)]` proc-macro preferred; callback interfaces soft-deprecated) + **async trait methods over FFI** are the injection bridge. BleAdapter sync 10-op / WifiAwareAdapter 12-op + WifiDirectAdapter 20-op async → foreign-future/oneshot → Kotlin `suspend`. Compatible with `#[async_trait]` already used in wifiaware.rs/wifi_direct.rs. | Q1 (foreign_traits L1, async-overview L1) |
| D-2 | **Explicit `tokio::runtime::Handle` injection** into every async poller thread. Do NOT rely on `#[uniffi::export(async_runtime="tokio")]` — INEFFECTIVE on exported-trait impls (issue #2576). Handle passed at construction. | Q1 (issue #2576, G-AND-3 spike) |
| D-3 | Foreign-trait method contract: **return `Result` with compatible error type** (else panic), **params by value** (refs unsupported, issue #2263). Existing adapter traits already pass by-value → 1:1 translation. | Q1 (#2263) |
| D-4 | **Toolchain pin**: UniFFI **0.31.x** (bindgen + proc-macro; 0.32 on docs.rs — re-check on upgrade, G-AND-1); cargo-ndk **4.1.2** (MSRV Rust 1.86); rust-android-gradle **0.9.6** (Gradle 8.x) **or Mullvad fork 0.10.1** (Gradle 9+) — the exact Gradle↔plugin pair is pinned at scaffold time (G-AND-4). | Q2 |
| D-5 | **NDK pinned** via `ANDROID_NDK_HOME` (r26 floor; SDK r28.2 current). ABI set {arm64-v8a (mandatory, Play 64-bit), armeabi-v7a, x86_64 (emulator)}; i686 dropped (G-AND-6). Generated Kotlin **committed** (ANDROID.md convention; uniffi-starter reference). | Q2 (G-AND-5/6) |
| D-6 | **App shell**: Kotlin **2.2.x** + Compose BOM **≥ 2024.01.00** (ANDROID.md floor) + **Hilt** (compile-time DI) + MVVM/Clean Architecture + `collectAsStateWithLifecycle()` (strong-skipping default). | Q3 |
| D-7 | **Identity crypto** (aligns IDENT-001 RED-0005): **Keystore TEE Ed25519** identity (hardware-backed Android 13+/API 33 floor; runtime fallback to Rust software keys on older/no-TEE devices per G-AND-2) + X25519 static advertisement. Session/onion keys stay in Rust engine (ephemeral — no HW anchor). **ECDSA P-256 conversion rejected.** StrongBox reserved only for optional AES DEK / P-256 rescue path (NOT v1; StrongBox excludes Ed25519). | Q4 (KeyMint v2 L1, CTS 399856239, hw-sign ED25519-first) |
| D-8 | **Platform floors**: targetSdk **34** / minSdk **26**. **Android 17 `ACCESS_LOCAL_NETWORK` (SDK 37) cliff documented** — v1 avoids it (implicit INTERNET grant), any future bump to 37+ must declare + runtime-request it (NEARBY_DEVICES group; gates TCP/UDP/mDNS/DNS-SD = whole IRIS data plane). `NsdManager`-mediated IPs exempt. Android 17 `BluetoothSocket.read()` **-1** handling (targetSdk 37 BLE). | Q5 (LNP L1, behavior-changes-17 L1) |

## 4. FFI / adapter layer (D-1..D-3)

- `crates/iris-android` re-exports the three adapter traits from `iris-core`
  transport modules and declares them `#[uniffi::export(foreign)]` (proc-macro —
  no `.udl`). `IrisEngine` mirrors `DesktopEngine` exactly: on construct it
  builds `TransportManager`, registers the injected adapters as `Transport`s
  (BLE/Wi-Fi Aware/Wi-Fi Direct), constructs `MessageEngine::new_with_telemetry`
  over `MemoryStorage` (PostgreSQL stays on desktop/server; Android uses
  metadata-only Room per KOTLIN_LAYER.md), and auto-spawns the inbox forwarder →
  `process_incoming` with a `subscribe_inbox` broadcast channel exposed to Kotlin.
- **Async foreign trait methods** (WifiAwareAdapter/WifiDirectAdapter) are
  declared as async `#[uniffi::export(foreign)]` trait methods. UniFFI generates
  Kotlin `suspend fun` implementations; Rust awaits them via the foreign-future/
  oneshot callback mechanism (piggybacks the Kotlin coroutine runtime — no
  Rust-side event loop thread).
- **Tokio handle injection (D-2)**: each Rust poller thread receives an explicit
  `tokio::runtime::Handle` at construction; all `adapter.poll_*()` awaits run
  through it. G-AND-3 spike at IMPLEMENT proves the generated Kotlin `suspend`
  functions compile + run against the existing `#[async_trait]` adapter
  definitions on this path (not via the broken `async_runtime` attribute).
- **Error contract (D-3)**: one compatible FFI error enum (per-adapter op → typed
  `Err`), methods return `Result<_, IrisFfiError>`; params by value (existing
  traits already pass owned handles/bytes — no reference smuggling).

## 5. Adapter lifecycle — FFI-contract absorption (NEW-WA-RT-108..112 + RT-010)

`AdapterLifecycle.kt` implements the carry-forward requirements from the
transport nodes (each maps to an AC in §7):

| Requirement | Lifecycle behavior |
|-------------|--------------------|
| NEW-WA-RT-108 | `connect()` NDP-reuse key switches to the **VERIFIED PeerId** once envelope resolution exists (candidate-only today, DEC-WA-0007) |
| NEW-WA-RT-109 | **Closed-NDP prune** + **multi-subscriber availability stream** (SharedFlow, not one-shot) |
| NEW-WA-RT-110 | **Per-call FFI timeouts** (platform calls seconds-scale worst case; `withTimeout`/synchronous watchdog) |
| NEW-WA-RT-111 / WIFIDIRECT RT-010 | **Idempotent start/subscribe** — same-session reuse, no new DiscoverySession/DiscoverySession on re-subscribe; `ensure_started()` not latched into failure |
| NEW-WA-RT-112 | **Ring-buffer outbox** instead of remove-0/rebuild (bounded, oldest-drop, per-destination eviction pattern from wifi_direct outbox) |

## 6. Platform plumbing (D-6, D-8)

- **FGS**: `IrisBleService` = `connectedDevice` FGS (API 34+) with
  `FOREGROUND_SERVICE_CONNECTED_DEVICE` type + `FOREGROUND_SERVICE` permission +
  POST_NOTIFICATIONS; started per transport need (BLE control plane durable
  trigger; Wi-Fi Direct re-arm window; Wi-Fi Aware production discovery).
- **Scanning**: PendingIntent pattern (Oreo+) + `SCAN_MODE_LOW_POWER` /
  `OPPORTUNISTIC`; scan-restart backoff ≥ 5/30 s (BLE-001 pattern).
- **WorkManager**: `IrisBackgroundSyncWorker` periodic cadence (15-min convention
  per ANDROID.md) for store-and-forward + relay checks; constraints-gated.
- **OEM battery-kill UX**: documented matrix (Samsung One UI Adaptive Battery,
  Xiaomi aggressive killers, Doze/app-standby buckets) + in-app guidance +
  `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` intent (user-initiated; never silent).
- **Permissions** (manifest + runtime, floors per ANDROID.md): BLE pre/post-31
  (`BLUETOOTH_SCAN/CONNECT/ADVERTISE` + `ACCESS_FINE_LOCATION`),
  `FEATURE_WIFI_AWARE` gate + `ACCESS_FINE_LOCATION`/`NEARBY_WIFI_DEVICES`
  neverForLocation, `FEATURE_WIFI_DIRECT` + P2P intents. **LNP**: targetSdk 34
  v1 → no `ACCESS_LOCAL_NETWORK` required; SDK-37 bump checklist documented in
  §8/§9.

  APK-size tradeoff for armeabi-v7a.

  Kotlin `BleAdapter` read loops must check -1 explicitly.

**Effective attribute contract for async foreign traits (0.31.2, from
standalone probe + macro source)**: attribute order must be
`#[uniffi::export(with_foreign)]` **then** `#[async_trait]` (uniffi outer;
reversed → E0195/E0261); `#[async_trait]` is mandatory for `async fn`
(plain `async fn` not dyn-compatible → E0038; generated impl applies
`::async_trait::async_trait` itself); trait objects must be `Arc<dyn Trait>`
(not `Box<dyn>`); `uniffi::setup_scaffolding!()` required in lib.rs (no
build.rs); `#[uniffi::export(async_runtime=...)]` is "not supported for
traits" (trait_interface.rs:29-31) — the explicit `Handle` pattern is the
supported path.
