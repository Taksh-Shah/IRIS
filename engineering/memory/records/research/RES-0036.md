# RES-0036 — INTERNET-ANDROID-001 jitter assertion failure

- **Date:** 2026-09-08
- **Trigger:** Focused Internet tests: 19 pass, 2 legacy backoff assertions fail
- **Maturity:** L1 AWS Well-Architected/SDK guidance + direct arithmetic audit

AWS reliability guidance requires bounded exponential backoff with jitter to
avoid synchronized retry spikes and a maximum retry interval. The implementation
contract in INTERNET.md specifies ±25%. At a capped 30,000 ms base, the exact
range is 22,500–37,500 ms. The legacy implementation/test used a 7,500 ms-wide
window centered by only 3,750 ms, which was ±12.5% while claiming ±25%.

Sources:

- https://docs.aws.amazon.com/wellarchitected/2023-04-10/framework/rel_mitigate_interaction_failure_limit_retries.html
- https://docs.aws.amazon.com/sdkref/latest/guide/feature-retry-behavior.html
- https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/

Decision: retain the corrected symmetric ±25% implementation and update stale
assertions/comments to the mathematically correct 22,500 ms lower bound. This is
not a production regression; the failed test correctly exposed documentation/code
drift in the old assertion.
