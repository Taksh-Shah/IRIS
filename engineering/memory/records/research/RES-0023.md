## 0. Executive summary (decisions at a glance)

- **G-1 ADOPT**: `cargo-nextest` as primary workspace runner. Up to 3× faster than `cargo test`; process-per-test isolation; retries + slow-test timeouts; leaky-test detection (default 100 ms, `LEAK`/`LEAK-FAIL` since 0.9.95); JUnit XML; partitioning/sharding (`--partition count|hash|slice:N/M`); CI profiles; run-record/replay; **no MSRV constraint on the tested project** (nextest is a standalone binary; repos can pin `nextest-version { required = ... }`). **Doctests are NOT run by nextest** (stable-Rust limitation, issue #16) → keep `cargo test --doc` step (tokio's CI does exactly this). Bench support (`cargo nextest bench`) is experimental (tracking #2874) — keep G-8 on criterion/`cargo bench` for now.
- **G-2 ADOPT**: wire BOTH as a recurring gate, different cadences — `cargo-deny check` (advisories + bans + licenses + sources) on every PR (fail-on: vulnerability/unsound/yanked per policy) + `cargo-audit` on schedule/PR for fast live-DB coverage (`--deny warnings`, committed `.cargo/audit.toml` for auditable suppressions with expires+reason; SARIF upload). RustSec advisory-db is actively maintained (Q1 2026 badge, OSV export, imported by GitHub Advisory DB). cargo-deny 0.20.2 (2026-05-28 crates.io) has the 4-check policy engine; `cargo-deny-action` for CI. Recommended mesh-crate policy: `[advisories]` deny + `unmaintained="workspace"`, `[bans] multiple-versions="deny"` + `wildcards="deny"`, `[licenses]` allowlist (MIT/Apache-2.0/ISC/Zlib etc.), `[sources] unknown-registry/unknown-git = "deny"`.
- **G-3 ADOPT-WITH-CONDITION**: three-layer concurrency/correctness stack — (a) **Kani** (bit-precise model checker; proves memory safety, panic-freedom, overflow freedom, `assert!` properties + experimental function contracts; does NOT support concurrency, Linux/Mac install only) for **pure functions**: codec decode bounds, fragment assembly math, rate-limiter/quota arithmetic, bloom/dedup math, CRC — CI job on Linux only; (b) **loom** (permutation testing under C11 model; exhaustive by default; `LOOM_MAX_PREEMPTIONS=2-3` practical; SeqCst-as-AcqRel → false alarms possible; not sound for load-buffering) for **leaf concurrent data structures** where `cfg(loom)` replacement types are feasible: dedup cache, replay high-water marks, quota counters; transport::manager-wide modeling is unrealistic (intrusive + many threads) — behavior stays tokio-test + property tests; (c) **tokio-test** (0.4.5, 2026-06-19) `assert_ready/pending/elapsed` + `tokio::time` pause for async engine behavior. Kani runs on Linux CI runner only (not Windows/macOS) — matrix implication.
- **G-4 ADOPT-WITH-CONDITION**: tarpaulin as **PR/merge gate** (`--fail-under <threshold>`; line coverage; outputs Json/Xml(cobertura)/Html/Lcov; v0.37.0, 2026, pre-1.0; Linux ptrace default = x86_64 only, llvm engine elsewhere) — threshold pragmatic ~80% workspace line (security path already 95.6%); **cargo-mutants as NIGHTLY/sharded sweep, NOT a hard PR gate** — mutation score is a trend signal; runtime cost is test-suite×mutant-count and on a 50k-LOC core with 613 tests scales to tens-of-minutes-to-hours → `--shard N/K`, `--file` scoping, `mutants.out/{caught,missed,timeout,unviable}.txt` triage. Both integrate with nextest (documented).
- **G-5 ADOPT**: PROTOCOL_CONFORMANCE fixtures = byte-level golden vectors derived from RFC 9171 (CBOR, CDDL Appendix B, IANA registries) + adversarial/resync fixtures (Meshtastic doc: "property-test your codec with random byte streams", bounded-recovery framing) + capture-based fixtures precedent (Wireshark BP dissector ships BPv7 TCPCL/UDPCL+BPSec pcapng). Interop evidence: ION↔µD3TN app-level interop (bping/bpecho/bpsink/AAP tools, IPNSIG PWG 20+ node network), Unibo-BP (IEEE 2024) interop-tested vs ION/DTNME/µD3TN, dtn7-rs with fuzz/ + docker/coreemu integration tests. Property-based simulation harness over existing SimMeshCoordinator/SimP2pCoordinator = the DTN-sim pattern (ns-3 BPv7 MR 2826 corroborates).
- **G-6 ADOPT**: reference CI pattern = official GitHub "Building and testing Rust" + tokio's own CI: `actions/checkout@v4/v6` → `dtolnay/rust-toolchain@stable` (or `@master` + `toolchain:` for matrix; components clippy,rustfmt; sliding-window MSRV expressions) → `Swatinem/rust-cache@v2` (keyed on rustc + Cargo.lock hash; per-matrix-cell `key:`) → `taiki-e/install-action@v2` `tool: cargo-nextest` (prebuilt, SHA256-verified) → `cargo nextest run --profile ci` + separate `cargo test --doc`; matrix `{ubuntu,macos,windows}-latest × {stable, MSRV-cell via include:}` with `fail-fast: false`; `CI=true` is always set by Actions → per-step `env: CI: "false"` only where a tool behaves differently under CI (e.g., interactive/pager behavior; nextest has `NEXTEST_NO_INPUT_HANDLER`); JVM suites on `actions/setup-java` (temurin ≤ 21, Gradle 8.9 constraint) separate job; fmt+clippy lint job once on ubuntu only; audit job `cargo audit`; coverage job tarpaulin (Linux only, docker+seccomp documented).
- **G-7 ADOPT**: commit golden/test-vector corpus as fixtures directory + byte-exact encode/decode harness both directions; catches the DISC-0009 class (timestamp hex arithmetic error in PROTOCOL_TEST_VECTORS.md) permanently; corpus = IRIS envelope/framing vectors + RFC 9171/RFC 8949-derived CBOR vectors + captured-PDU fixtures. Back-compat regression guard for BLE/Wi-Fi Direct framing and codec.
- **G-8 ADOPT (scaffold now, measurements deferred)**: criterion 0.8.x (criterion-rs org; old `0.5` from bheisler repo is stale) as the only stable-channel benchmark option — `#[bench]` is nightly-only and a hard error on stable ≥ 1.88; `divan` is the attribute-style alternative. Pattern: `[dev-dependencies] criterion`, `[[bench]] name=... harness=false`, `criterion_group!`/`criterion_main!`, `std::hint::black_box`, baselines via `--save-baseline`/`--baseline`; cargo-criterion CLI remains "experimental" (official guidance) — no CI regression gate. CPU-path benches (codec, crypto, routing score, fragment) run on CI without hardware → build harness now, gate later; battery/physical-transport perf remains **BLK-0005 hardware-gated** (deferral rationale preserved).

**Key facts that change DESIGN**: (1) nextest does NOT run doctests (separate `cargo test --doc` step mandatory, tokio precedent); (2) Kani is Linux/Mac-only and Kani does NOT model concurrency → formal proofs target pure functions on Linux runner, Windows/macOS matrix = behavioral tests only; (3) cargo-mutants must not be a hard PR gate initially (runtime cost + flakiness sensitivity — mutants require a deterministic test suite); (4) tarpaulin default ptrace engine is Linux x86_64 only → workspace coverage gate runs on Linux ubuntu runner (llvm engine elsewhere); (5) loom requires `cfg(loom)` code intrumentation (replacement types) and is not sound for SeqCst/load-buffering → scope to leaf structures, treat as proof-of-absence with documented limits.

### Q3 — Kani / loom / tokio-test / proptest applicability to message_engine + transport::manager (G-3)
**VERDICT G-3: ADOPT-WITH-CONDITION** — Kani for pure functions (Linux CI), loom for leaf concurrent structures (cfg(loom)), tokio-test for async behavior; no tool models the full transport::manager — that stays tokio/property/adversarial suites.
- Kani (official getting-started, model-checking.github.io): bit-precise model checker; proves memory safety (UB), panic-freedom, overflow, user assertions; optional experimental function contracts; harnesses `#[kani::proof]` + `kani::any()`/`kani::assume()`; "may run out of resources"; **"There is support for a fair amount of Rust language features, but not all (e.g., concurrency)"**; install "Rust 1.58+; Linux or Mac" — https://model-checking.github.io/kani/, https://github.com/model-checking/kani (L1, accessed 2026-08-18)
- Kani scale/credibility: ASE 2026 (IEEE/ACM Intl. Conf. Automated Software Engineering, Industry Track) paper: MIR→CBMC compilation; contracts upgrade panic-freedom→functional correctness on industrial projects (6 previously-unknown bugs); >16,000 harnesses/change in the Rust standard-library verification campaign — https://arxiv.org/abs/2607.01504 (L2, accessed 2026-08-18)
- loom (docs.rs official): permutation testing of concurrent executions under the C11 memory model with state reduction (CDSChecker/Toplas'16); exhaustive by default; `LOOM_MAX_PREEMPTIONS=2-3` "enough to catch most bugs"; **intrusive** — code must use loom replacement types (`cfg(loom)`); **unsupported**: `SeqCst` treated as `AcqRel` (→ false alarms, issue #180), load-buffering not modeled (→ not sound); MAX_THREADS limit — https://docs.rs/loom/latest/loom/, https://github.com/tokio-rs/loom (L1/L4, accessed 2026-08-18)
