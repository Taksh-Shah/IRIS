## Question

What is the actual maximum LoRa payload size for IRIS P0 messages in India?

## Source

1. Semtech LoRa Calculator / Regional Parameters
2. The Things Network - Spreading Factors
3. LoRaWAN IN865 Regional Parameters
4. WPC India ISM band regulations (865-867 MHz)
5. https://iottools.dev/lorawan-payload-calculator

## Finding

**Raw LoRa (P2P, no LoRaWAN):**
- Physical layer max payload: 255 bytes (Semtech SX1276/SX1262)
- Variable length mode: 1-255 bytes
- This is what IRIS edge nodes will use (direct LoRa, not LoRaWAN)

**LoRaWAN IN865 (India) - if IRIS ever uses LoRaWAN:**
| Data Rate | SF/BW | Max MAC Payload | Application Payload |
|-----------|-------|----------------|-------------------|
| DR0 | SF12/125kHz | 51 bytes | 50 bytes |
| DR1 | SF11/125kHz | 51 bytes | 50 bytes |
| DR2 | SF10/125kHz | 51 bytes | 50 bytes |
| DR3 | SF9/125kHz | 115 bytes | 114 bytes |
| DR4 | SF8/125kHz | 222 bytes | 221 bytes |
| DR5 | SF7/125kHz | 222 bytes | 221 bytes |

**India Regulatory (WPC):**
- Frequency: 865-867 MHz (IN865 band)
- Max power: 1W EIRP (30 dBm)
- Duty cycle: No explicit limit (unlike EU 1%)
- Alternative: 433.05-434.79 MHz ISM band also available

**Key insight**: Raw LoRa P2P supports 255 bytes. IRIS P0 targets raw LoRa (not LoRaWAN) for direct edge-to-edge communication. The 255-byte limit is correct for the physical layer.

**But**: At higher spreading factors (SF12 for maximum range), airtime for 255 bytes is very long (~2+ seconds), increasing collision risk and battery drain. For emergency P0, this may be acceptable (infrequent, critical messages).

## Implications

1. IRIS P0's 255-byte LoRa budget is correct for raw LoRa
2. The existing P0 envelope calculation (~186 bytes fixed + 69 bytes payload) fits within 255 bytes
3. IRIS does NOT use LoRaWAN (peer-to-peer LoRa only)
4. For maximum range, SF12 provides -137 dBm sensitivity but longest airtime
5. The protocol must support fragmentation for larger messages over LoRa
