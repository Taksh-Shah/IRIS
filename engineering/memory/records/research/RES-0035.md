# RES-0035 — INTERNET-ANDROID-001 first compile failure

- **Date:** 2026-09-08
- **Trigger:** `cargo check -p iris-core -p iris-android --all-features`
- **Scope:** Three compile errors in the new relay/FFI tranche
- **Maturity:** L1 Rust Reference and standard-library documentation

The Rust Reference specifies that match guards borrow pattern-bound values before
an arm is selected; an owned `Vec<u8>` therefore cannot be moved into
`try_send` from the guard. The standard `Option` documentation specifies
`ok_or_else` for converting `Option<T>` into the `Result<T, E>` required by `?`.

Sources:

- https://doc.rust-lang.org/reference/expressions/match-expr.html
- https://doc.rust-lang.org/error_codes/E0507.html
- https://doc.rust-lang.org/std/option/enum.Option.html#method.ok_or_else

Decision: move `try_send(bytes)` into the selected match arm, and convert the
hex helper's `Option<[u8;32]>` with a lazy typed `IrisFfiError`. No protocol or
architecture change is needed.
