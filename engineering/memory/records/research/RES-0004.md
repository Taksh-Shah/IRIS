### Gaps Identified

1. **Connection pooling**: The design uses `conn.lock().await` but doesn't specify how multiple concurrent readers/writers are managed. For a relay-heavy scenario, a connection pool (e.g., `deadpool` or `bb8`) is needed.

2. **Storage compaction**: After mass eviction, SQLite doesn't automatically reclaim space. `VACUUM` or `PRAGMA auto_vacuum` should be documented.

3. **Backup/restore**: No mechanism for exporting/importing the database for device migration.

4. **Metrics integration**: The `metrics` table exists but no storage-specific metrics are defined (e.g., query latency, cache hit rate, storage utilization).

5. **Crash recovery**: WAL mode provides crash recovery, but no explicit startup integrity check is documented beyond SQLCipher's implicit check.

6. **Multi-device sync**: Not in scope for v1, but should be noted as a future consideration.

## Recommendation

The design is **production-ready for v1**. The gaps (connection pooling, compaction) are implementation details that can be addressed during MSG-001 implementation. No blocking issues found.
