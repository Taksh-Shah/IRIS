# RES-0033 — Android trusted-peer QR and alias UX

**Date:** 2026-09-08  
**Node:** ANDROID-PAIR-001  
**Maturity:** L1 primary platform documentation + existing IRIS identity design  
**Verdict:** PROCEED WITH CONDITIONS

## Questions and evidence

1. **Which scanner works during an outage?** Google ML Kit offers an APK-bundled
   barcode model (`com.google.mlkit:barcode-scanning:17.3.0`) that is available
   immediately; its Play-services alternative may need a first-use download.
   IRIS therefore uses the bundled model despite the approximately 2.4 MB APK
   increase. Source: https://developers.google.com/ml-kit/vision/barcode-scanning/android
2. **How should camera frames be handled?** Android recommends CameraX
   `PreviewView`, lifecycle binding, `ImageAnalysis`, latest-frame backpressure,
   and closing every analyzed `ImageProxy`. Sources:
   https://developer.android.com/media/camera/camerax/preview and
   https://developer.android.com/media/camera/camerax/analyze
3. **What may the QR/manual path trust?** Scanner and pasted text are hostile
   inputs. Android's platform security guidance requires strict validation of
   externally supplied navigation/input data. Source:
   https://developer.android.com/privacy-and-security/risks/unsafe-use-of-deeplinks
   IRIS therefore accepts only its fixed-size, Ed25519-signed advertisement as
   a trusted pairing credential. A bare PeerId + X25519 value is not sufficient:
   it lacks the existing signed identity-to-encryption-key binding.
4. **How is human trust confirmed?** Preserve IDENT-001's order-independent
   five-character SAS on both phones. Scanning/pasting adopts only an
   Unverified advertisement; explicit matching-SAS confirmation promotes it to
   Verified and only then saves the alias.

## Decision

- Add an offline QR generator and bundled QR-only scanner.
- Use a versioned text envelope around the existing signed advertisement;
  retain raw-hex acceptance for backwards-compatible paste.
- Provide one Contacts surface with Show my code, Scan, Paste code, select,
  rename and forget actions.
- Make the remote/manual workflow copy the same signed pairing code; do not
  re-enable the insecure legacy bare-key registration route.
- Keep aliases local, unique case-insensitively, trimmed and length-bounded;
  cryptographic routing continues to use the PeerId/key record.

## Known limitations

- QR scanning needs a foreground CAMERA runtime grant.
- Physical two-phone message delivery is a human-run hardware gate after APK
  deployment; automated tests validate parsing, QR generation, alias policy,
  trust transitions and command resolution.
