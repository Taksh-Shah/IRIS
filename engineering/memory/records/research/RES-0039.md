# RES-0039 — Dual-stack authenticated LAN test failure

**Date:** 2026-09-08  
**Node:** INTERNET-ANDROID-001  
**Trigger:** First mutual-LAN-auth test run passed compilation but two IPv4
loopback sends fell through to `NotConnected` against the IPv6 wildcard listener.

Microsoft documents that Windows IPv6 sockets default to `IPV6_V6ONLY=1`; a
dual-stack socket must set that option to zero *before bind*. Socket2 exposes
the cross-platform `set_only_v6(false)` API and documents that it permits
IPv4-mapped IPv6 clients:

- https://learn.microsoft.com/en-us/windows/win32/winsock/dual-stack-sockets
- https://docs.rs/socket2/latest/socket2/struct.Socket.html#method.set_only_v6

**Decision:** retain one NSD-advertised port, construct it explicitly with
socket2, set `IPV6_V6ONLY=false` before binding `[::]:0`, then wrap the
nonblocking listener in Tokio. Do not fall back to IPv4-only and do not remove
the authentication handshake.

**Maturity:** L4 OS/API documentation plus L1 live failure evidence.
