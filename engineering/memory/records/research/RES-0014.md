## 1. Delivery-probability prediction beyond RFC 6693

- **RFC 6693 (PRoPHET v2)** remains the IETF-standard probabilistic predictor for opportunistic/DTN routing: encounter-history-derived delivery predictability (DP) with delta-bounded direct transitivity, gamma aging, GRTR/GTMX+/GTHR forwarding strategies. Already implemented for IRIS in ROUTE-002 (`prophet.rs`). ML-001 must be understood as an *experimental replacement/augmentation of the DP computation*, not a protocol change — the forwarding layer (GTMX+ / Spray-and-Wait) stays intact.
- **ML-classification framing**: Dudukovich & Papachristou, "Delay Tolerant Network Routing as a Machine Learning Classification Problem" (NASA Glenn, 2018; IEEE doc 8541460) frames relay selection as classifying "which neighbor is most likely to deliver to destination" from message-history features. Multiple decision-tree/random-forest/XGBoost replications (incl. open GitHub `ML-Classification-DTN-Routing`) report XGBoost as best classifier, PRoPHET beating Epidemic in delivery — an independent confirmation of the L2 baseline's utility. Level 2.
- **ML-MaxProp** (arXiv:2508.20077, 2025): hybrid MaxProp + supervised XGBoost over features {contact frequency, buffer occupancy, hop count, message age, TTL}; evaluated in the ONE simulator with Helsinki SPMBM mobility; reports higher delivery probability, lower latency, reduced overhead vs MaxProp/Spray-and-Wait baselines under resource-constrained post-disaster settings; notes DRL/transformers demand heavy training impractical for constrained emergency nodes; statistical validation via paired t-tests / Wilcoxon. Level 2 (preprint) / Level 3 (sim-only figures).
- **RL-augmented PRoPHET** (Rezaei & Derakhshanfard, *Wireless Networks* 31:2909–2923, Springer, 2025): replaces/refines PRoPHET's delivery-probability computation with a reinforcement-learning-based criterion; reports suitable delivery ratio and delay under intermittent connectivity. Confirms the specific ML-001 hypothesis: the DP value itself is learnable. Level 2.
- **DTRB** (Rolla & Curado, *Eng. Appl. of AI* 26(10):2243–2250, 2013): Multi-Agent RL (MARL) flooding-based routing with gossip-style time-since-last-meeting rewards; fewer messages than epidemic-style with similar delay and lower overhead in urban mobility (OMNeT++). Older but the canonical MARL-in-DTN reference. Level 2.
- **Temporal-graph line (adjacent)**: link/contact prediction on temporal graphs is mature outside DTN: TGN (Rossi et al., arXiv:2006.10637), EvolveGCN, TGNN surveys, and specifically **TGA-TTLR** (2026, "Contact Prediction using Temporal Graph Analysis for TTL-aware DTNs") and MDPI *Electronics* 13(5):957 (2024, "Spatial-Temporal Attention TCN-Based Link Prediction for Opportunistic Networks") show TCN/attention contact prediction applied to opportunistic networks. These are candidate *offline-simulation* baselines, but their on-node cost is Level 3 and IRIS has no central trainer (see §4).

## 2. Gateway / egress prediction

- **Concept**: OppNet/DTN taxonomy (ScienceDirect, opportunistic-network overview) distinguishes scheduled gateways (DTN) from random neighbor-gateways (OppNet). For IRIS, gateway egress = a node with working Internet (INTERNET-001 transport / GW-001 GatewayManager). Predicting *which* node will next have egress, or *when* a known gateway becomes reachable, is the gateway-prediction sub-problem of ML-001.
- **PodNet / opportunistic Internet offloading** (Bernhard et al. 2010; PSN literature): content reaches the Internet by routing toward a device with 3G/Wi-Fi; user devices act as mules between hubs. This is exactly IRIS's GW-001 model (self-internet-gateway + adopted gateway candidates + mesh-only fallback). ML's contribution: score candidate gateways by predicted egress *timing* rather than static quality.
- **Ferry/data-mule prediction**: ferry-based dissemination (message-ferry literature; UTA thesis, McMaster thesis) uses dedicated mules with predictable routes. For ML-001, the testable claim is: if contact patterns are periodic (vehicle_relay scenario in SIM-001), a learner can predict gateway contacts better than the static GW-001 quality weights; if contacts are random, learning gains vanish (matching the OppNet random-neighbor warning). Level 3 estimate from literature pattern; no IRIS-specific benchmark exists.
- **Mobile data offloading** (Rebecchi et al. 2015 survey; IEEE 2013 offloading survey): D2D offloading uses encounter probability + social communities to select seed users — a gateway-adjacent selection problem with the same feature vocabulary (encounter probability, community). Level 2.

## 3. Learned routing for DTN (RL / GNN)

- **GNN-enhanced DTN routing** (ICCBN 2024, ACM 3688636): GNN learns network structure to route in UAV-assisted DTNs with rapidly changing topology; grounded in Advanced PRoPHET (ICCSN '09) which uses *average* delivery predictabilities to avoid routing jitter. Signals: topology-structure-aware routing is an active 2024–2025 line. Level 2 (conference) / Level 3 (limited evaluation).
- **Graph attention + MARL, decentralized** (Lozano-Cuadra, Soret, Sanchez Net, Cauligi, Rossi — arXiv:2510.20436, 2025): fully decentralized routing for lunar DTN relay-to-lander under intermittent connectivity; graph attention-based MARL. Directly relevant for IRIS's fully-distributed constraint; but targets a *known contact plan* (Lunar DTN), unlike IRIS's unpredictable-mobility primary mode. Level 2.
- **DRL under uncertain contact plans** (HAL/INSA-Lyon, 2025): DRL for DTN routing with uncertain contact plans — positions DRL as the answer when contact plans are probabilistic rather than fixed. Level 2.
- **DRL for disaster-recovery DTN** (Wen & Tan, ICFTIC 2024): DRL routing in disaster networks; notes heavy training cost as practical limit (echoed by ML-MaxProp). Level 2/3.
- **RouteNet-TGNN** (JCM 2026, 21(2)): temporal GNN with GRU for multi-step QoS (delay/jitter/loss) forecasting on dynamic networks; -27.5% delay error vs static GNN; framed for SDN/digital-twin controllers — *not* for autonomous in-situ mesh nodes. Illustrates where TGNNs are proven (central prediction with global view) vs where they are not (IRIS). Level 2/3.
- **CGR capacity/buffer improvements** (Alhajj & Corlay, arXiv:2410.15546): deterministic Contact Graph Routing (CGR, the scheduled-contact-plan routing) extended with capacity/buffer management — the scheduled-plan alternative family. IRIS is not scheduled-plan in primary mode; CGR is only relevant for a future satellite/relay-planning sub-mode. Level 2.

## 4. Resource constraints & applicability to IRIS

- **IRIS principles (authoritative constraint)**: ML-001 is P3 *experimental only*, never in the critical delivery path (ARCHITECTURAL_PRINCIPLES.md #5/#6). Any L3 route must be a *shadow/experiment* comparing against the L2 PRoPHET baseline; it must not affect delivery of P0/P1 traffic.
- **Feature cost**: the ML-001-usable feature vocabulary is already in-band in iris-core: contact frequency, delivery predictability (DP), hop count, buffer occupancy, message age, TTL, gateway link status (GW-001 GatewayHealthState). No new sensors needed. The cheap models (XGBoost/decision tree/naive Bayes, feature count ≈ 6) match what ML-MaxProp and the NASA classifiers report as practical for constrained nodes — Level 3 but well-corroborated.
- **Inference vs training asymmetry**: the literature consistently splits "expensive training (offline, central)" from "cheap inference (online, on-node)". For IRIS: training can only happen in SIM-001 (offline, seeded, deterministic); a trained model could later be distilled to a compact form for on-device inference, but on-device deployment is out of scope (BLK-0005 hardware; and never in critical path).
- **What is testable in SIM-001 without hardware**: delivery-probability prediction (LSTM/MLP vs PRoPHET DP), gateway-egress timing prediction, and learned forwarding decisions — all feasible in the existing `crates/iris-core/src/sim/` harness (seeded ChaCha8Rng, dense_mesh/partition_carry/vehicle_relay scenarios, SimMetrics). Determinism and same-seed A/B vs L2 are already supported (ROUTE-002 evidence: same-seed deterministic, parity + lower overhead).
- **Energy/memory**: XGBoost single-tree inference ~µs and single-digit KB; LSTM/MLP inference on ARM ~sub-ms for 6 features; DRL training and TGNNs are not feasible on-node without a trainer — consistent across ML-MaxProp, DRL-disaster, lunar-MARL sources. Level 3 estimates; IRIS should not rely on them for P0.

## 5. Experimental evaluation design (grounded recommendations)

1. **Primary comparison**: L3-learned delivery-probability (MLP/LSTM or XGBoost over DP-features) vs L2 PRoPHET DP, inside the same SIM-001 forwarding chain (GTMX+ + Spray-and-Wait untouched). Metric: delivery ratio, overhead ratio, p50/p95 latency per SimMetrics — same-seed A/B.
2. **Gateway sub-experiment**: gateway-egress timing prediction (predict next gateway contact in vehicle_relay periodic scenario) vs GW-001 static quality weights; quantify gain only where contacts are periodic (vehicular/scheduled), expect parity under random mobility.
3. **Scenarios**: reuse dense_mesh, partition_carry, vehicle_relay; add a *periodic-ferry* scenario (known contact plan) and a *random-walk* scenario as the two extremes that bound expected learning gain.
4. **Determinism**: same-seed anchors (result_anchor pattern) for both arms; statistical significance is secondary (P3) but a paired t-test/Wilcoxon on delivery ratio across ≥10 seeds mirrors ML-MaxProp methodology.
5. **Meaningful result threshold**: an L3 win must exceed the ROUTE-002-recorded L2 overhead win margins AND hold across both periodic and random scenarios; a P3-experimental result is publishable/educational even at parity, because it bounds when ML *does not* help.
6. **Never in path**: L3 decisions recorded as shadow metrics only; no code path from L3 output to actual P0/P1 forwarding.

## 6. Gaps / risks

- **No real mobility traces in IRIS**: all SIM-001 scenarios are synthetic; ML tuned to synthetic traces may not transfer (the ML-DTN literature's acknowledged limitation — "reliance on synthetic traces, high computational overhead, limited reproducibility" — ML-MaxProp §4.3). Mitigation: periodic-vs-random spectrum, avoid overfitting claims.
- **Training-data leakage in-sim**: DP features already encode the training signal; naive L3 can be a tautology. Experiment must define held-out destinations/time windows.
- **Central-vs-decentral gap**: the strongest SOTA results (TGNN, DRL with contact plans) assume central knowledge; IRIS is fully distributed — only per-node-local features are legitimate. Centralized results must be flagged Level 3 for IRIS transferability.
- **Maturity asymmetry**: RFC 6693 PRoPHET is battle-tested (Level 1); every ML alternative is Level 2–3 with sim-only evidence. This is exactly why ML-001 is P3 EXPERIMENT and not a routing change.
- **No open-source IRIS-specific baseline**: literature numbers (delivery gains +7–8% [MLP-based router], ML-MaxProp improvements) come from ONE simulator with different mobility/buffer assumptions; they are directional, not contractual.
