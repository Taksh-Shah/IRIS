## Question

Is the WIFIDIRECT-001 v1 design — Android Wi-Fi Direct (P2P) discovery (DNS-SD) + `createGroup`/`connect` + TCP data plane over the GO, triggered by the BLE control plane — still correct in 2026? What Android API floors, group-security model (WPA2 floor vs WPA3-SAE), client-limit architecture, discovery-durability strategy, persistent-GO/band behavior, OOB provisioning option, Linux wpa_supplicant surface, and 2024-2026 security findings must the DESIGN stage bake in? And does any SOTA change the documented "iOS NOT available / MCSession Apple-only" and other WIFI_DIRECT.md propositions?

## 0. Executive summary (decisions at a glance)

- **Q1 ADOPT**: classic `WifiP2pManager.discoverPeers()/discoverServices()/createGroup()/connect()/removeGroup()` fully supported + actively extended through Android 16 (API 36) and beyond — no deprecation in 2026 (USD-based discovery, R2, DIR via API 36; CONNECTION_REQUEST_DEFER… API 37). DPP (Wi-Fi Easy Connect) is infra-client-only, NOT a P2P path. Coexistence channel-avoidance (Android 12+) covers Wi-Fi Direct (`COEX_RESTRICTION_WIFI_DIRECT`, `WifiAvailableChannel` API 34).
- **Q2 ADOPT with condition**: P2P group default = WPA2-Personal (PSK/AES-CCMP); **WPA3-Personal (SAE) is now spec-supported** on Wi-Fi Direct R2-capable devices (API 36 `WifiP2pGroup.getSecurityType()` WPA3_SAE / WPA3_COMPATIBILITY; PCC modes in `WifiP2pConfig`). IRIS floor = WPA2; SAE gated behind R2 capability probes (`isWiFiDirectR2Supported`/`isPccModeSupported`) as later-phase upgrade. OWE is infra-only (not P2P). PMF Required in WPA3-Personal Only Mode (WPA3 spec v3.5).
- **Q3 ADOPT with caveat**: WFA mandates 1:1 as mandatory case, one-to-many optional; the "1 GO + 8 clients" is a vendor/HAL ceiling, NOT a universal WFA guarantee. STA+P2P concurrency is optional per WFA + device/HAL-dependent. Architect N-client admission + GO-side connection table rather than hard-coded 8.
- **Q4 ADOPT**: DNS-SD (Bonjour) pre-association service discovery is the documented correct mechanism, preferred over device-name filtering. Framework P2P find window is **120 s** (`DISCOVER_TIMEOUT_S`) — WIFI_DIRECT.md's "30-s" is an app-level re-arm cadence, not a platform limit. Discovery is best-effort on OEM builds → BLE control plane remains the durable trigger (already IRIS pattern).
- **Q5 ADOPT**: autonomous GO via `createGroup()` persists until `removeGroup()`/teardown; persistent groups stored + reinvokable (Android + wpa_supplicant `p2p_invite`). Band hints via `setGroupOperatingBand` — **API 29** (WIFI_DIRECT.md says "API 30+", correct at DESIGN); values AUTO/2GHZ/5GHZ/6GHZ; band-constrained GO creation FAILS if unsupported. Client IP: IPv4 DHCP or new IPv6-link-local provisioning mode. MAC randomization tied to persistent-group presence (source.android.com).
- **Q6 DEFER (v1)**: WPS deprecated client-mode (API 28); WPS-PIN is an attack target (CVE-2021-0326 and adjacent P2P RCEs). NFC OOB exists in P2P spec §3.1.2.7 but not exposed via Android P2P API. Modern path = Wi-Fi Direct R2 pairing bootstrapping (API 36 `WifiP2pPairingBootstrappingConfig`, incl. OUT_OF_BAND "Over BLE"). IRIS best practice: skip WPS entirely, push group passphrase over the authenticated BLE control plane (R2 OOB-style), PBC only for legacy fallback.
- **Q7 ADOPT**: wpa_supplicant exposes full P2P surface (`p2p_group_add [persistent] [freq]`, `p2p_connect [pbc|pin] [go_intent]`, `p2p_service_add bonjour`, `p2p_invite`, `p2p_prov_disc`, `p2p_get_passphrase`, group iface `p2p-wlan0-N`). **IP/DHCP is NOT automatic parity** — wpa_supplicant does no DHCP; each platform's glue assigns GO IP + DHCP server. IRIS Linux nodes own that glue (GO static + dnsmasq/udhcpd; GC DHCP). Android's 192.168.49.1 GO IP must be verified in AOSP at DESIGN (G-WD-2).
- **Q8 ADOPT with GATE (OS patch floor)**: no new unauthenticated P2P-specific RCE in Android 2024-2026 found, but threat class is real: w1.fi advisory 2026-1 (unauthenticated management frames → memory corruption, pre-wpa_supplicant v2.12), 2026-3 (SAE NULL-deref DoS), kernel Wi-Fi driver CVE stream (CVE-2024-26895/27053/47712/47724/56539/46755, CVE-2025-40321, CVE-2026-31780/46069). Gate: Android SPL ≥ 2021-02 (fixes CVE-2021-0326 RCE), Linux wpa_supplicant ≥ 2.12, kernel with 2024-2026 Wi-Fi driver fixes. **WPS-PIN must not be used.**

**Key doc corrections carried to DESIGN**: `setGroupOperatingBand` = **API 29** (not API 30+); framework P2P find window = **120 s** (not 30 s — 30 s is app re-arm cadence); client ceiling "1 GO + 8 clients" = vendor/HAL, not WFA guarantee; WPA3-SAE available via R2 (API 36) capability-gated; Android GO IP 192.168.49.1 = practice-stable but verify in AOSP (G-WD-2).

### Q2 — Group security method (WPA2 vs WPA3-SAE)
**VERDICT: ADOPT with condition** — default WPA2-Personal (PSK/AES-CCMP); WPA3-Personal (SAE) now a real spec-supported option on R2-capable devices (API 36). IRIS floor = WPA2; SAE capability-gated, later-phase.
- "Wi-Fi Direct supports WPA2 encryption" — https://developer.android.com/develop/connectivity/wifi/wifi-direct (L1); WFA FAQ: group networks protected by "security features certified under the WPA2 program," separate security domain from infra — https://www.wi-fi.org/knowledge-center/faq/can-a-network-based-on-devices-certified-under-the-wi-fi-direct-program-cross (L1)
- `WifiP2pGroup.getSecurityType()` returns `SECURITY_TYPE_WPA2_PSK`, `SECURITY_TYPE_WPA3_COMPATIBILITY` (Compatibility Mode), `SECURITY_TYPE_WPA3_SAE` — https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pGroup (L1)
- `WifiP2pConfig` PCC: `PCC_MODE_CONNECTION_TYPE_R2_ONLY` → "GO: Configured to support WPA3-Personal connections"; `LEGACY_OR_R2` → "WPA3-Personal Compatibility Mode … WPA3-Personal and WPA2-Personal simultaneously" — https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pConfig (L1)
- WPA3 spec v3.5: PSK AKM 00-0F-AC:2 vs SAE AKMs 00-0F-AC:8/24; PMF Required in WPA3-Personal Only Mode; CCMP-128 pairwise minimum — https://www.wi-fi.org/system/files/WPA3%20Specification%20v3.5.pdf (L1)
- WFA Current Work Areas: "strong demand to update Wi-Fi Direct to leverage new Wi-Fi technologies, such as Wi-Fi 6 and WPA3…" (certification update in progress) — https://www.wi-fi.org/current-work-areas (L1)
- Best practice: WPA2 floor for interop (all certified P2P devices); SAE only when `isWiFiDirectR2Supported()`/`isPccModeSupported()` confirms R2; do NOT rely on OWE (infra-only).

### Q3 — Per-GO client limits + STA/P2P concurrency
**VERDICT: ADOPT (with implementation caveat)** — WFA 1:1 mandatory, one-to-many optional; "1 GO + 8 clients" is vendor/HAL ceiling, not universal WFA guarantee. STA+P2P concurrency optional per WFA + device/HAL-dependent.

### Q6 — NFC/QR/OOB provisioning; WPS status
**VERDICT: DEFER (v1)** — WPS deprecated client-mode (API 28) + WPS-PIN is attack target; DPP/QR is infra-only (not P2P); NFC OOB exists in P2P spec but not exposed via Android P2P API.
