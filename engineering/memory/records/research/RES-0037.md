# RES-0037 — Full-suite and relay liveness/backpressure failure research

**Date:** 2026-09-08  
**Node:** INTERNET-ANDROID-001  
**Trigger:** Full regression failures plus independent red-team interim findings.

## Observed evidence

1. `cargo test --workspace --all-features --no-fail-fast` did not reach test
   execution for `iris-desktop`: its pre-existing D2-only test calls
   `tokio::task::AbortHandle::is_aborted()`, which does not exist in Tokio
   1.53.1. The Internet, relay, and Android crates compiled before this error.
2. Android full JVM testing executed 98 tests; 97 passed and the known
   `DesignTokenParityTest.command set matches the desktop mirror` failed because
   Android advertises `/all`, `/name`, and `/contacts` while the desktop mirror
   does not. Focused Internet/NSD tests remain green.
3. Red-team inspection found that idle relay sessions are closed after 120 s
   while no heartbeat task exists, relay queue capacity is bounded only by
   message count (64 x up to 1 MiB per session), and client ACK timeouts leave
   stale `pending_acks` entries and can return a failed writer to the pool.

## Authoritative evidence

- Tokio 1.53 `AbortHandle` exposes `abort`, `id`, and `is_finished`; it has no
  `is_aborted`. Cancellation is asynchronous, so completion is observed using
  `is_finished` or by awaiting the owning `JoinHandle`:
  https://docs.rs/tokio/latest/tokio/task/struct.AbortHandle.html
- Tokio `timeout` cancels the wrapped future on expiry by dropping it; caller
  state inserted before awaiting therefore needs explicit cleanup:
  https://docs.rs/tokio/latest/tokio/time/fn.timeout.html
- Tokio bounded MPSC capacity counts queued *messages*, not bytes. A frame-count
  bound alone is not a memory budget when frames vary up to 1 MiB:
  https://docs.rs/tokio/latest/tokio/sync/mpsc/fn.channel.html
- RFC 9174 uses application keepalives and terminates sessions after an
  implementation-defined period without a received message; this supports a
  heartbeat interval shorter than both peers' idle deadline:
  https://www.rfc-editor.org/rfc/rfc9174.html
- Kotlin `Set.equals` requires identical cardinality and membership, confirming
  the Android parity failure is real command-surface drift rather than ordering:
  https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/-set/

## Decision

- Do not retry either full suite unchanged.
- Keep the desktop D2 test and command-surface parity mismatch outside this
  Internet recovery node; both predate its diff and already reproduce at their
  precise owners. Report them as isolated full-suite blockers, while continuing
  Internet-scoped workspace/package verification.
- Before security acceptance, add authenticated relay liveness, substantially
  reduce per-session queued byte exposure and bound global sessions, and always
  remove an ACK waiter plus evict/abort a suspect pooled connection on ACK
  timeout.

**Maturity:** L4 official APIs/RFC plus L1 live repository evidence.
