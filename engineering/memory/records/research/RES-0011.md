## Headline corrections to the research brief

1. **The equations quoted in the brief are PRoPHET v1 (Lindgren et al., 2003), not RFC 6693.** RFC 6693 §2.1.2 defines: **Eq. 1 (direct)**: `P(A,B) = P(A,B)_old + (1 − delta − P(A,B)_old) · P_encounter(intvl)` where `delta` sets the upper bound (1−delta); **Eq. 2 (aging)**: `P(A,B) = P(A,B)_old · gamma^K` (matches); **Eq. 3 (transitivity)**: `P(A,C) = MAX(P(A,C)_old, P(A,B) · P(B,C)_recv · beta)` — **MAX form, not additive**. First-ever/low encounter sets `P = P_encounter_first` (SHOULD 0.5). `P(A,A) = 1`.
2. **RFC 6693 §7 is IANA, not comparative studies.** The PRoPHET-vs-epidemic evidence lives in Lindgren et al. 2003/2004 (peer-reviewed) and Grasic et al. CHANTS 2011; §3.6 points to lindgren_06 for strategy evaluation.
3. **No newer IETF/IRTF PRoPHET spec.** RFC 6693 (IRTF Experimental, Aug 2012) is current; RFC 9171 (BPv7, Nov 2021) obsoleted RFC 5050 (which 6693 references) but does not touch PRoPHET — routing sits above the BPA; 6693's BPA-interface (§2.2) maps cleanly onto BPv7.

## (b) Design implications for IRIS

1. **Implement RFC 6693 v2 semantics** (Eq. 1 with delta, interval-scaled P_encounter, MAX transitivity) — not the v1 additive forms currently in `docs/routing/OPPORTUNISTIC_ROUTING.md` (P_INIT 0.75, BETA 0.25, GAMMA 0.98 are v1).
2. **Hop budgets ↔ GTMX+**: IRIS P1-3=5 / P4-7=3 maps to `NF_max`; use **GTMX+** (copy cap + P_max monotonicity, §3.6) so bundles are never re-forwarded to a node with lower DP than previously seen — an anti-oscillation guard independent of ForwardedCache.
3. **Cold start**: binary SaW (ADR-0005, EXP-ROUTE-002 L=8) is the correct fallback — matches Lindgren's original guidance (fall back to epidemic-like spread when no DP history) and RFC 6693's P_encounter_first=0.5 cold-start P.
4. **SCF integration**: per-destination DP subsumes the static 0.9/0.6 heuristic in SCF-001; keep the 0.9 as the direct-contact ceiling analog (P_(A,A)=1) and rank relay candidates by DP.
5. **State budget**: DP table is O(N) per node (10k nodes ≈ 40 KB/node — ADR-0005 is correct read per-node; O(N²) is only the aggregate). Transitivity fills it toward N; bound churn with P_first_threshold=0.1 discard (§2.1.3.2).
6. **Aging unit**: RFC allows any time unit; pick IRIS I_typ from SIM contact frequencies (≈10–30 min for BLE crowd, hours for vehicle relays) and derive gamma via Appendix C — do not hard-code a 1-hour aging interval.
7. **Forwarding threshold**: RFC's default is relative GRTR (`P(B,D) > P(A,D)`), not a fixed floor; use GTHR's `FORW_thres` as the P_forward_min equivalent only where high-DP epidemic spread is wanted (P0/P1 escalation).
8. **SIM-001 parity with ONE**: add **overhead ratio** and **average hop count** to SimMetrics (delivery ratio, latency, storage already present); keep seeded multi-run + confidence reporting (Lindgren used 5 runs/95% CI).
9. **Asymmetry**: DPs are directional (RFC §2.1); never force `P(A,B) = P(B,A)` — the brief's "§4.3 link-state symmetry note" is actually §2.1.2/§2.1.1 of the RFC.

## (d) Contradictions with existing IRIS constants

- `OPPORTUNISTIC_ROUTING.md` constants (P_INIT 0.75, BETA 0.25, GAMMA 0.98, 3600-s aging unit) are **v1 values contradicting RFC 6693 §3.3** (0.7/0.5/0.9/0.999 defaults, MAX transitivity, interval-scaled P_encounter). Rebase on RFC before implementation.
- ROUTE-001's **10-min known-path expiry** is next-hop freshness — orthogonal to DP aging, but IRIS must not reuse the 10-min clock as the DP aging unit without deriving gamma for it (Appendix C), else DPs over-age.
- ADR-0005 L=8 (binary) vs `OPPORTUNISTIC_ROUTING.md` per-priority L table (P1=5, P2=3) — resolve to one policy; EXP-ROUTE-002 evidence favors L=8 with per-priority caps tied to hop budgets.
- SCF 0.9/0.6 static heuristic has no RFC analogue; DP replaces it (design change to SCF contact ranking, not an RFC violation).

## (e) Risk notes

1. **RFC 6693 is IRTF Experimental**, not standards track; treat as research-grade baseline, re-check dtnrg for evolution before production.
2. **DP message-exchange attack surface** (§6.1.1–6.1.5): black-hole, spoofing, fake ACKs, `P` flooding/manipulation — RIB/DP exchange must ride the authenticated control plane (IRIS Ed25519 identities; per-message crypto does not automatically cover routing metadata).
3. **MaxProp caution**: its beat-oracle result is bus-DTN specific; the "PRoPHETv2 ≥ MaxProp/SaW" claim rests on CHANTS simulations — do not over-index either way at low node counts.
4. **Transitivity staleness** in post-disaster churn can point DPs at dead zones; P_first_threshold discard bounds this but a hard cap on transitive-only entries should be considered (O(N) per node).
5. **ONE default models omit contention/energy** — IRIS SIM-001's simulation-reality gap must be documented per RESEARCH_POLICY when claiming delivery-ratio numbers.
6. **Parameter drift between nodes** degrades but does not break routing (RFC §2.1.2.1) — acceptable for mixed-version field nodes, but keep IRIS defaults compiled-in and versioned.

**Open questions → SIM experiments**: gamma for IRIS I_typ; GTMX+ NF_max vs hop-budget interplay; L per priority tier. (EXP-ROUTE-001/002 exist; add EXP for gamma sweep.)
