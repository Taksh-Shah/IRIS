## 2. Architecture & IPC

- **Process model**: Core (Rust) owns all IPC routing + global state; WebView process renders system webview (WebView2 / WKWebView / WebKitGTK — not bundled). Engine handle belongs in the Core.
- **IPC primitives**:
  - **Commands** (`#[tauri::command]` + `invoke`) — request/response, serde typed, sync or async. Async commands execute on `tauri::async_runtime::spawn` (tokio). Sync commands run on main thread — don't block. Async commands must return `Result<_, _>`.
  - **Events** (`emit`/`emit_to`) — broadcast, JSON strings only, **not designed for low latency/high throughput**; async listeners may process out of order.
  - **Channels** (`tauri::ipc::Channel<T>`) — ordered, fast streaming, **recommended for high-frequency data** (inbound message stream, delivery status).
  - `tauri::ipc::Response` — raw byte buffers without JSON overhead.
- **Capabilities/ACL** (v2 security): commands + plugin permissions must be granted per-window in `app.security.capabilities` (e.g. `"core:default"`). No matching capability → no IPC access.
- **tauri-build**: `tauri-codegen` parses `tauri.conf.json`, embeds/hashes/compresses assets. Command names from `lib.rs` cannot be `pub` (E0255 macro-glue collision); separate command modules use `commands::foo`.
- **tauri.conf.json v2**: `identifier` required (reverse-DNS, alnum + `-` + `.`), `build.beforeDevCommand`/`devUrl` optional (omit → CLI built-in dev server + simple hot-reload over `frontendDist`), `app.withGlobalTauri` (inject `window.__TAURI__`, no npm needed), `frontendDist` path to static assets (`index.html` entry).

## 3. Frontend: plain HTML/JS vs Vite+React

- **Plain HTML/JS is first-class** — `create-tauri-app` ships an officially maintained "vanilla" template; docs recommend starting there. "Tauri is frontend agnostic... acts as a static web host."
- Minimal no-npm setup:
```jsonc
{ "productName": "iris-desktop", "identifier": "in.iris.mesh.desktop",
  "build": { "frontendDist": "../ui" },
  "app": { "withGlobalTauri": true } }
```
- Frontend calls: `window.__TAURI__.core.invoke('cmd', {…})`, `window.__TAURI__.event.listen(...)`, `window.__TAURI__.core.Channel`.
- Vite+React: `beforeDevCommand: "npm run dev"`, `devUrl: "http://localhost:5173"`, shows for HMR/TS. Trade-off justified when UI grows.

## 4. State management + tokio + async commands

- **Managed state**: `app.manage(EngineHandle::new(...))`; `tauri::State<'_, T>` in commands; `app.state::<T>()` elsewhere (Manager trait). No `Arc` needed — Tauri wraps in Arc. Send+Sync required.
- **Pitfall issue #2533**: async command signatures canNOT contain borrowed types (`&str`, `State<'_, T>`) — use owned types (String) or wrap return in `Result<…, ()>`.
- **Runtime**: singleton tokio runtime via `tauri::async_runtime` (spawn/spawn_blocking/block_on/channel). Background engine tasks: `tauri::async_runtime::spawn(async move { engine.run().await })` so they die with the app.

```rust
struct EngineHandle(Arc<iris_engine::Engine>);

#[tauri::command]
async fn send_message(engine: tauri::State<'_, EngineHandle>,
                      req: SendMessageRequest) -> Result<MessageId, String> {
    engine.0.send(req).await.map_err(|e| e.to_string())
}
```

## 5. Cross-platform constraints

- **Windows**: MSVC Rust toolchain; **WebView2 preinstalled on Win10 1803+/Win11 — no webview setup for dev**. MSI targets need VBSCRIPT optional feature.
- **Linux**: webkit2gtk-4.1 + libxdo + libayatana-appindicator3 + librsvg2 dev packages (4.1 API — v2 requires it). Tray needs appindicator.
- **macOS**: Xcode / CLI tools; WKWebView OS-provided.
- System webview rendering differences (WebKitGTK 4.1 vs WebView2 vs WKWebView) = functional risk; logs as GAP-DESKTOP-001.

## 6. Testing (no GUI)

- `tauri::test` module (crate feature `test`, "unstable"): `mock_builder()` → `Builder<MockRuntime>`, `mock_app()`, `get_ipc_response(&webview, InvokeRequest)`, `assert_ipc_response(...)`. Async commands go through the same IPC path — fully testable without a window.
- Strategy: **the bulk of logic is in iris-core (already GUI-free)** — the Tauri layer should be a thin adapter (commands → engine calls), unit-test the engine directly, use MockRuntime only at the command boundary.
- Frontend: `@tauri-apps/api/mocks` (mockIPC, mockWindows). E2E: `@wdio/tauri-service` (WebDriver).

## 8. Background/daemon capability

- **Default**: Tauri exits when last window closed on Win/Linux; macOS keeps running.
- **Kept-alive daemon**: `RunEvent::ExitRequested { api, code, .. }` → `if code.is_none() { api.prevent_exit(); }`; must provide tray "Quit" → `app.exit(0)`; ignored for `restart()`.
- **Hide instead of close**: `WindowEvent::CloseRequested { api, .. }` → `window.hide()` + `api.prevent_close()`.
- **System tray**: feature `tray-icon`; `TrayIconBuilder`. Linux: tray click events unsupported (menu only).
- **BackgroundThrottlingPolicy**: for hidden webview that must process pushes, set `"disabled"`/`"throttle"` (else suspended).
- **Implication**: Core process = daemon; singleton tokio runtime + spawned tasks stay alive while process lives.

## Decision implications for DESKTOP-001

1. Adopt Tauri v2 (`tauri = "2"`), vanilla HTML/JS + `withGlobalTauri` + `frontendDist` first.
2. Stream inbound messages over `Channel`; events only for low-rate lifecycle; never per-message payloads via events.
3. `app.manage(EngineHandle)`; commands thin `async fn → Result<_, String>`; Send+Sync state.
4. Test shell with `tauri::test` MockRuntime; engine keeps GUI-free suite.
5. Daemon: tray + `prevent_exit()`; `BackgroundThrottlingPolicy` disabled.
