# DISC-0008: Autonomy Failure Mode — No Execution Supervisor Loop

**Type**: Discovery
**Date**: 2026-08-11
**Node**: META (control plane)
**Author**: Principal Architect
**Status**: ACTIVE

## Problem

The IRIS agent completes one node/task, persists state, writes a checkpoint, and then voluntarily terminates the session. The user must manually send another prompt to continue.

This is NOT an engineering graph execution system. It is a single-task executor.

## Root Cause Analysis

### Symptom
After PROTO-001 completed, the session ended with "Next session: run /resume". The system correctly persisted all state but did not continue to STORE-001.

### Root Causes (identified)

1. **No execution supervisor loop**: The system relies on the LLM's willingness to continue after each action. The model is not instructed to treat each action as one iteration in an ongoing loop.

2. **Commands are prompts, not loops**: `/resume`, `/next`, `/checkpoint` are command prompts that tell the model what to do. After executing, the model returns a summary. There is no mechanism to inspect durable state and continue.

3. **`maxSteps` not configured**: The `opencode.jsonc` agents do not specify `maxSteps`. OpenCode's default agentic step limit applies. When the model exhausts its step budget or decides to stop, the session ends.

4. **No machine-readable execution state**: `CURRENT_STATE.md` is prose. A supervisor cannot programmatically determine "what is the current action, what was the last result, and what should happen next" from prose alone.

5. **No explicit state machine**: The system has no formal states (IDLE, EXECUTING, CHECKPOINTING, TRANSITIONING, BLOCKED, HUMAN_GATE). Without explicit states, the supervisor cannot make deterministic continuation decisions.

6. **No stall detection**: Even if a loop existed, there's no mechanism to detect "N iterations without progress" and trigger recovery.

### Failure Mode Classification

| Attribute | Value |
|-----------|-------|
| Category | Architecture |
| Severity | CRITICAL |
| Recurrence | Deterministic (always occurs) |
| Impact | Blocks autonomous execution |
| Recoverability | Full (architecture upgrade needed) |

## Required Changes

1. Create machine-readable `execution-state.yaml`
2. Create `supervisor.md` agent with explicit state machine
3. Create `/autonomous` command with real continuation
4. Update `/resume` to auto-continue when work is eligible
5. Configure `maxSteps` for autonomous agents
6. Implement execution log and observability
7. Implement stall detection and recovery
8. Implement failure classification and recovery paths
