# FAIL-0009 — Android Internet transport reports unavailable and mesh stays down

- **Date:** 2026-09-08
- **Node:** INTERNET-ANDROID-001
- **Source:** User-observed shipping-app run
- **Result:** FAIL — `RADIO UNAVAILABLE`, mesh not connected, status down

## Evidence captured

The report is user-observed. The original failing run did not preserve its APK
revision, relay configuration, or logcat. A vivo 2004 Android 12/API-31 phone
(`b2fbcd39`) became ADB-visible later in the repair session, but that does not
retroactively supply the missing failure evidence.

Repository inspection reproduces deterministic configuration and control-flow
causes:

1. The shipping `IRIS_RELAY_ENDPOINTS` default is empty, making relay availability
   false even on a validated network.
2. Android passes relay socket addresses but never enables `Relay` mode or supplies
   the TLS server name.
3. The bundled relay server uses an embedded self-signed localhost certificate and
   private key, while the production client trusts public WebPKI roots.
4. `IrisEngine::start_all` counts only BLE, Wi-Fi Aware, and Wi-Fi Direct; it can
   return “no transport started” while Internet/LAN is viable.
5. NSD-resolved LAN peers are stored only inside `InternetTransport`, not published
   to discovery/routing; service loss is ignored.
6. Relay has no trusted-peer rendezvous bootstrap, so two Internet-only peers do
   not learn or connect to each other.

## Disposition

Do not retry the unchanged APK. `RES-0034` is the mandatory fresh research and
diagnosis pass. Repair is tracked in new P0 node `INTERNET-ANDROID-001`; software
tests precede a two-phone LAN/WAN hardware rerun. A deployed CA-valid relay and
ADB-visible phones are external acceptance resources, not assumed evidence.

## 2026-09-08 focused compile failure

The first post-hardening library test compile failed because the newly added
signed-plaintext ingress regression test referenced `std::time::Instant` without
importing it into the test module. The relay binary compiled independently, so
this was classified as a test-fixture scope error, not an Internet protocol
failure. The Rust standard-library documentation confirms `Instant` is imported
from `std::time`; the test module now does so before the test is retried.

The first identity-scoped connection-pool run then hung in LAN setup. Focused
instrumentation localized the wait to a second acquisition of `pool` inside the
`else` branch of an `if let` whose scrutinee contained `pool.lock().await`.
The Rust Edition Guide documents that, before Edition 2024, an `if let`
scrutinee temporary lives through the `else` branch; this kept the Tokio mutex
guard alive and self-deadlocked. The lookup is now evaluated in its own block so
the guard is dropped before either branch. No unexplained retry was performed.

The first Android compile of the serialized NSD adapter failed four callback
overrides because expression bodies ending in `Log.i`/`Log.w` inferred Android's
integer log result instead of Java `void`/Kotlin `Unit`. Official Kotlin function
documentation confirms single-expression return types are inferred whereas a
non-value block body defaults to `Unit`. Those four callbacks now use block
bodies; no runtime or protocol behavior was changed by this correction.

The exhaustive 865-test core run passed 864 tests and failed the broadcast
forwarding regression because the test asserted that the outbound queue was
non-empty immediately after enqueue. `enqueue_relay` calls `Notify::notify_one`,
and Tokio documents that this wakes the waiting consumer; the background
delivery loop can therefore drain the queue before the assertion. The durable
`relayed` metric is incremented synchronously by the same successful path and is
now asserted instead. The isolated behavior is rerun before another broad suite.

The next combined focused-test command supplied three positional name filters;
Cargo rejected the second one before running that command. The Cargo Book's
syntax permits one optional `TESTNAME` filter. Subsequent focused groups are
therefore invoked as separate `cargo test` commands. The preceding isolated
broadcast test itself passed.

The full Android JVM suite passed 99 of 100 tests. The sole failure is the
pre-existing cross-platform command-surface parity check: Android advertises
`all`, `myadvert`, `fingerprint`, `forget`, `name`, and `contacts`, while the
desktop JavaScript mirror lacks them. This does not exercise or gate Android
Internet, NSD, TLS, relay, or messaging behavior; the focused Internet/NSD tests
and Kotlin compilation pass. It remains a separately scoped desktop UI parity
defect rather than being “fixed” by advertising unwired desktop commands.

The first configured APK build invocation passed a dotted endpoint directly as
a PowerShell argument and Gradle parsed `.0.0.1:7777` as a task path. Official
Gradle documentation confirms project properties may instead be supplied via
`ORG_GRADLE_PROJECT_*`; the build was rerun using process-scoped environment
properties and completed successfully. This was CLI quoting, not source failure.

The first full `iris-android` Rust test pass completed 9/10 and timed out in
`round_trip_delivers_over_shared_mesh`. The test manually connected a transport
but relied on the independently scheduled `DiscoveryManager` scan to populate
the routing table. Tokio's official scheduling documentation confirms spawned
tasks are scheduled independently and should be synchronized explicitly. The
test now reports the same routing-visible peer observation as `scan_once()`
immediately after its manual connection. The isolated regression and the full
10-test Android Rust suite then passed.
