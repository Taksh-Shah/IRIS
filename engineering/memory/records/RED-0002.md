## Executive Summary

The top concern — **shadow isolation** — holds. There is no code path from L3
output (`ShadowDecision`, `FeatureVec`, `score`) to any P0/P1 forwarding
decision: `shadow_features` is `&self` read-only, `record()` is side-effect-free
on routing state, the shadow path consumes no RNG, and ML-001 AC-2's
byte-identical anchors are empirically confirmed (integration test green). No
panic, no NaN, no unbounded loop is reachable from the shadow machinery under
default configuration.

The review found **0 CRITICAL, 0 HIGH, 1 MEDIUM, 2 LOW, 4 INFO** issues. The two
LOW findings (ML-RT-02 feature-bound hardening, ML-RT-03 unsorted-contact
underflow) were **fixed in-pass** by the supervisor. The MEDIUM (ML-RT-01,
unseeded sim MessageId) is a pre-existing sim-wide behavior, tracked as a
known_limitation — not changed in this P3 experimental pass to avoid touching
the global ID generator.

## Detailed Findings

### ML-RT-01 — MEDIUM — Unseeded sim message IDs vs the determinism claim

- **File**: `crates/iris-core/src/protocol/message_id.rs:22-24`; `crates/iris-core/src/sim/mod.rs:695`; `crates/iris-core/src/routing/scf.rs:60`
- **Finding**: Sim messages get IDs from `MessageId::new_v7()` = `Uuid::now_v7()`
  (OS RNG via getrandom) — **not seeded**. AC-1/AC-2/AC-5 ("same seed →
  byte-identical") currently hold only because random ID bytes do not change
  `StoreKey` ordering / decisions in the current scenario shapes. A scenario
  with same-priority/same-expiry injections (StoreKey tie-breaks on
  `message_id`) would change forward order → loss-RNG draw order → divergent
  anchors despite the same seed.
- **Severity**: MEDIUM (determinism hardening; not an isolation breach)
- **Disposition**: KNOWN_LIMITATION — pre-existing sim-wide behavior; fixing
  requires seeding the ID generator for sim builds, which is out of scope for a
  P3 experimental pass and could perturb the whole ROUTE-002 evidence corpus.
  Revisit before relying on AC-1/AC-2 as general invariants.

### ML-RT-02 — LOW — Un-clamped DP feature slots / no finite guard

- **File**: `crates/iris-core/src/sim/ml/features.rs:34-40`; `crates/iris-core/src/sim/mod.rs:292-294`; `crates/iris-core/src/routing/prophet.rs:80-87,220`
- **Finding**: Feature slots 0-2 (`p_b_r`, `p_self_r`, `p_b_self`) are clamped
  only by the *default* ProphetConfig's bounded Eq.1 math; `p_direct` is never
  explicitly clamped and no `is_finite()` guard exists in the
  feature→score→fit pipeline. A NaN/Inf config value (public `ProphetConfig`)
  flows → NaN feature → NaN score → NaN weights → silently-false agreement.
- **Severity**: LOW
- **Disposition**: **RESOLVED in-pass (2026-08-14)** — supervisor clamped the
  three DP slots to `[0,1]` at the feature boundary in `sim/mod.rs:shadow_features`
  and added a `debug_assert!(all finite)` in `FeatureVec::new`.

### ML-RT-03 — LOW — Unsorted contact times underflow

- **File**: `crates/iris-core/src/sim/ml/experiment.rs:169-173`; `crates/iris-core/src/sim/ml/predictor.rs:86-89`
- **Finding**: `evaluate_gt` and `GtPredictor::fit` assume sorted contact
  times (documented); unsorted input → `w[1]-w[0]` on `u64` underflows (panic
  in debug, wrapped garbage in release).
- **Severity**: LOW
- **Disposition**: **RESOLVED in-pass (2026-08-14)** — supervisor added a
  defensive `sort_unstable()` in both `evaluate_gt` (sorted copy) and
  `GtPredictor::fit`, plus a regression test `gt_tolerates_unsorted_contact_times`.

### ML-RT-04 — LOW — Unbounded shadow recorder

- **File**: `crates/iris-core/src/sim/ml/mod.rs:54-56`
- **Finding**: `record()` is an unbounded `Vec::push`; a large
  contacts×messages sim accumulates every decision with no cap → OOM on the
  experiment harness.
- **Severity**: LOW (harness-only; production forwarding path untouched)
- **Disposition**: KNOWN_LIMITATION — acceptable for the experimental harness;
  a max-samples cap can be added if sims grow.

### ML-RT-05..07 — INFO — minor hardening notes

- **ML-RT-05** (`with_shadow` double-attach silently replaces recorder,
  `sim/mod.rs:175-178`): INFO — could `debug_assert!` none, but replacing is
  safe (no panic).
- **ML-RT-06** (age slot unbounded magnitude, `sim/mod.rs:287-288,291`): INFO —
  graceful (no NaN), but log-scaling the age slot would improve conditioning.
- **ML-RT-07** (shadow-path node indexing assumes validated contacts,
  `sim/mod.rs:273-291`): INFO — pre-existing harness assumption, shared with
  `forward_to`.

## Explicitly Reviewed and NOT Flagged

- **Shadow isolation (probe 1)**: `shadow_features` is `&self` (sim/mod.rs:265)
  and reads only `p_for`, `hops_by_msg`, `usage_bytes`, `clock`; `record()`
  pushes to `ShadowRecorder.samples` only (ml/mod.rs:54); `decide_forward` is
  computed before the record call (sim/mod.rs:352→355) so recording cannot
  feed back. **PASS**.
- **RNG/loss coupling (probe 2)**: shadow machinery consumes zero RNG draws;
  `is_lost()` call count/order unchanged by shadow attach; AC-2 byte-identical
  test green. **PASS**.
- **Panic/index safety (probe 5)**: `split_at_mut` Greater branch returns
  `(src,dst)` correctly (sim/mod.rs:454-463); `exchange_on_contact` correct.
  **PASS**.
- **Determinism (probe 6)**: ML code is order-deterministic (`snapshot()`
  `total_cmp`+PeerId tie-break, Vec iteration, no HashMap-order dependence).
  **PASS** (with ML-RT-01 note above).
- **Threshold calibration (probe 7)**: `while t < 1.0 { t += 0.05 }` terminates
  (~20 iterations), never NaN. **PASS**.
- **Injection surface (probe 8)**: `with_shadow` misuse safe; no panic on
  attach-twice/drop. **PASS**.
