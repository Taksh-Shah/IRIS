# DEC-0002 — Operator-Directed Storage Engine Pivot to PostgreSQL

**Record ID**: DEC-0002
**Date**: 2026-08-13
**Author**: Execution Supervisor (operator directive)
**Status**: RATIFIED (operator direction)

---

## Decision

STORE-001 (`iris-storage`) uses **PostgreSQL** as the durable message store,
replacing the SQLite + SQLCipher design originally prescribed by `STORAGE.md`
and ADR-0004. Directive from the operator: *"Strictly use only PostgreSQL, no
sqlite."* Credentials are supplied at runtime via environment
(`IRIS_PG_PASSWORD` — never committed to the repository).

## Rationale

- Operator direction supersedes the prior engine choice.
- PostgreSQL provides stronger operational guarantees (concurrency, durability,
  managed deployment) than embedded SQLite for the multi-node mesh server tier.
- The `MessageStorage` seam (MSG-001) is engine-agnostic, so the pivot is
  contained to the `iris-storage` crate — no changes were required in `iris-core`.

## Implementation (WP-2)

- `crates/iris-storage/` with `tokio-postgres = "0.7"`.
- `src/schema.rs` — idempotent DDL (`CREATE TABLE IF NOT EXISTS`), mirrored
  columns + `envelope_cbor BYTEA` for byte-exact reconstruction via the
  PROTO-001 canonical CBOR codec.
- `src/pg.rs` — `PgStorage: MessageStorage` over a shared multiplexed client;
  `INSERT ... ON CONFLICT DO NOTHING` dedup; quota enforcement (StorageFull for
  non-P0 over quota; P0 always accepted); `gc_once`.
- `src/eviction.rs` — expired-first, then one-row-at-a-time lowest-priority
  eviction until target bytes reached; **P0 never evicted while unexpired**
  (`priority > 0` guard, INV-ROUTE-003).
- `src/gc.rs` — 60 s background GC task.
- Tests: 10/10 unit + 1/1 M3 engine-over-Postgres integration;
  `cargo test --workspace` green, clippy 0 warnings.

## Effects

- `STORAGE.md` updated to describe the PostgreSQL backend and remove
  SQLite/SQLCipher-prescriptive text (kept as historical context).
- Workspace deps: add `tokio-postgres`; remove `rusqlite` /
  `rusqlite_migration`.
- ADR-0004 (SQLite) is now superseded for the storage engine choice. ADR updates
  are queued for a doc pass.

## Debts / Follow-ups

- In-transit TLS (NoTls on loopback for dev; per-deployment TLS required).
- At-rest encryption + storage key derived from node master key — deferred to
  CRYPTO-001 gate (BLK-0001).
- Connection pooling / reconnect for the deployment harness.
