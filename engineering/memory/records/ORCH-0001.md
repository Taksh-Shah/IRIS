### WP-A — Envelope Codec & Wire Types (PROTO-001 implementation arm) — ✅ COMPLETE 2026-08-13

**Purpose**: Everything (MSG, STORE, ROUTE, SCF) operates on `Envelope`. This WP
makes PROTO-001's design executable. Strict prerequisite for all other WPs.

**Delivered in `crates/iris-core`**:
- `src/protocol/mod.rs` — module root; exports `Envelope`, `ContentType`, `EnvelopeError`.
- `src/protocol/envelope.rs` — Envelope struct (fields 1–18 per `MESSAGE_ENVELOPE.md`), integer-key CBOR codec.
- `src/protocol/codec.rs` — canonical CDE serialization (RFC 8949 §4.2): sorted integer keys, definite lengths, `encode_for_signing()` (omits fields 8, 15, 16+ per ADR-0011) and `verify_signing_bytes()`.
- `src/protocol/content_type.rs` — ContentType enum (payload types 1–16) + `assign_priority()` per `PRIORITY_MODEL.md`.
- `src/protocol/message_id.rs` — `MessageId` 16-byte UUIDv7 (RFC 9562).

**Evidence (M1 complete)**: byte-exact canonical CDE vector for P0 SOS = 237 B; round-trip; signing-scope membership; extension tolerance; error paths; 61/61 tests, clippy 0 warnings. Corrections recorded (DISC-0008: payload capacity 84 B; DISC-0009: test-vector timestamp hex).

**Type normalization (must resolve first)**: `message_id` today is `[u8; 32]` in `message.rs`; wire spec is **UUIDv7, 16 bytes** (MESSAGE_ENVELOPE.md field 2). DEDUPLICATION.md describes a 24-byte BLAKE3 id. Decision: canonicalize to `[u8; 16]` UUIDv7 as the wire/存储 message_id (envelope is authoritative); dedup exact-set keyed on those 16 bytes. Also align `MessagePriority` variant names with PRIORITY_MODEL.md (P0=SOS, P1=Medical, P2=Location, P3=EmergencyText, P4=Normal, P5=Image, P6=Voice, P7=Video) — current `message.rs` names differ.

**Dependencies**: PROTO-001 (COMPLETE), Cargo deps to add: `ciborium`, `serde_bytes`, `uuid` (v7), `blake3`, `thiserror`; dev: `proptest`, `hex-literal`.

**Acceptance mapping** (→ ACCEPTANCE_POLICY.yaml):
- PROTOCOL `additional`: encoding test vectors pass (`PROTOCOL_TEST_VECTORS.md`), round-trip property test passes (Active-State: "Round-trip property test: PENDING (needs implementation)" — this WP closes it), size budget verified (P0 < 255 B assertion test), ADR retained.
- Component-level: error cases tested (parse/version/signature-bytes paths).

### WP-1 — MSG-001 Message Engine (P0, COMPONENT)

**Deliverables in `crates/iris-core`** (per MSG_DESIGN.md + RUST_CORE.md):
- `src/message_engine/mod.rs` — `MessageEngine` + `MessageEngineConfig` + `MsgEngineError`; owns storage (Arc<dyn MessageStorage>), TransportManager, internal broadcast; spawns GC + starvation timers.
- `src/message_engine/lifecycle.rs` — `MessageStatus` (CREATED→PENDING_SEND→IN_TRANSIT→DELIVERED→ACKNOWLEDGED, EXPIRED, DELIVERY_FAILED) + guarded transition fn.
- `src/message_engine/queue.rs` — `PriorityQueue` (BinaryHeap<QueuedMessage>), P0 preempt, FIFO within priority, delivery_prob tiebreak, **starvation prevention** (60 s P0 gate → insert one P1+).
- `src/message_engine/expiry.rs` — TTL enforcement at insert/dequeue/relay, clock-skew budget (300 s), GC on 60 s interval.
- `src/message_engine/dedup.rs` — relay Bloom filter (100 K @ 0.1% FPR, ~1.44 MB) + exact LRU (10 K), 144 h window.
- `src/message_engine/ack.rs` — ACK tracker: pending map, E2E/CUSTODY/GW ack types per ACKNOWLEDGEMENTS.md, per-priority timeout/backoff table.
- `src/message_engine/fragment.rs` — fragment reassembler (30 s timeout) + emit fragmentation when > transport MTU. (P5–P7 scope; required by acceptance criterion #6.)
- `src/message_engine/storage.rs` — **MessageStorage trait** (interface to WP-2): persist/load/update_status/evict_expired/evict_by_priority/get_queue.
- Crypto seam: `src/message_engine/crypto.rs` — `CryptoProvider` trait (sign/verify/encrypt/decrypt) with a **dev/test no-op backend**; real CRYPTO-001 implementation swappable when BLK-0001 resolves (see Risk Register).

**Dependencies**: WP-A (codec), STORE-001 trait (interface only), TRANSPORT-001 (COMPLETE, `TransportManager` in `src/transport/manager.rs`).

**Acceptance mapping** (COMPONENT + MSG_VERIFICATION criteria):
- COMPONENT `additional`: public API documented; error cases explicitly tested; integrated with adjacent components (verification mileage at M3/M5).
- MSG-001 criteria 1–10 from MSG_DESIGN.md §Acceptance Criteria become #[test]s: lifecycle transitions, P0 preemption, TTL at 3 points, Bloom+LRU dedup, exponential backoff, reassembly timeout, starvation, thread-safety (Arc<RwLock>+Semaphore test), storage-pressure degradation, observability hooks.

## 2. Parallelization

```
WP-A (envelope codec) ── strict prerequisite; ships first
        │
        ├──▶ WP-1 MSG-001 ──────────┐  (parallel: trait interface, no SQL)
        │                            │
        ├──▶ WP-2 STORE-001 ─────────┤  (parallel: implements MessageStorage trait)
        │                            │
        ├──▶ WP-3 DISCO-001 ─────────┘──▶ WP-4 ROUTE-001 ──▶ WP-5 SCF-001 (parallel with WP-6)
        │                                               └──▶ WP-6 SIM-001
```

- **Independent / concurrent**: WP-1, WP-2, WP-3 may proceed **simultaneously** after WP-A lands (WP-1 needs only the `MessageStorage` *trait* definition; WP-2 implements it in a separate crate; WP-3 touches only transport abstraction). Agent pool: implementer for MSG-001 + storage implementer + discovery implementer in parallel.
- **Sequential**: WP-A → {WP-1, WP-2, WP-3} → WP-4 → {WP-5, WP-6}. WP-4 is the join point (needs MSG + DISCO). WP-5 and WP-6 are mutually parallel after WP-4.
- **Not on active path** (do not dispatch implementers): CRYPTO-001/IDENT-001 (BLK-0001), BLE-001 device adapters (BLK-0005), EMERG-001 (needs IDENT-001 + human gate).
